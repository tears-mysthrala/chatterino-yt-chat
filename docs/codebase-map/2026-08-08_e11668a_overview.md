## Observed purpose

**Observed in code:** This is a read-only Chatterino plugin that obtains public YouTube Live Chat data, normalizes actions/renderers, builds Chatterino message specifications, and delivers them to bound splits. Evidence: `README.md`, `info.json`, `init.lua`, `src/init.lua`, `src/youtube/polling.lua`, and `src/c2_adapter.lua`.

**Observed in code:** Runtime permissions are `Network`, `FilesystemRead`, and `FilesystemWrite`; runtime dependencies are Chatterino's Lua environment and vendored `libs/json.lua`. Evidence: `info.json`, `SECURITY.md`, `libs/json.lua`.

## Structure and execution flow

```text
init.lua -> src/init.lua -> commands + persistence + offline monitor
                         |
YouTube HTML/Innertube -> continuations -> actions -> renderers
                                             |          |
                                             +-> messages/* -> builder
                                                                  |
                                                           c2_adapter -> splits
```

**Observed in code:**

- `src/youtube/` owns URL normalization, watch-page parsing, Innertube request construction, continuation selection, action/renderer dispatch, and polling.
- `src/messages/` converts hostile/partial YouTube structures into a defensive normalized event IR and then into Chatterino message specs.
- `src/state/` owns persistent channel bindings, schema migrations, recoverable writes, active streams, split membership, and message deduplication.
- `src/support/` owns time, backoff, bounded rate limiting, logging/redaction, and validation.
- `src/c2_adapter.lua` concentrates Chatterino API access for HTTP, timers, channels, and message delivery.
- `tests/` provides unit, integration/mock-Chatterino, fuzz, and load coverage; `fixtures/` contains action/continuation payloads.
- `.github/workflows/ci.yml` runs metadata checks, lint, formatting, host allowlist and secret checks, fixture validation, tests, and reproducible packaging.

## Data and process boundaries

**Observed in code:** There is no database, Ecto-style repository, worker queue, or independent daemon. Long-lived behavior is timer/callback driven inside the Chatterino plugin process (`src/youtube/polling.lua`, `src/support/clock.lua`, `src/c2_adapter.lua`).

**Observed in code:** Persistent state is schema-versioned JSON in `YT_CHAT.json`, with `.tmp` and `.bak` recovery paths. Persisted content is settings, channels, and split bindings; Innertube keys, continuations, and chat payloads are not part of the schema (`src/state/persistence.lua`, `src/state/migrations.lua`, `SECURITY.md`).

**Reasonably deduced:** `src/youtube/polling.lua` is the central operational coordinator because it joins network IO, retry/backoff, stream state, parsing, deduplication, rendering, and delivery.
